## Arcade Icon Bug Investigation - CORRECTED ✅

**Time:** ~02:45 UTC → ~03:00 UTC (correction)
**Context:** Hikari reported arcade/game icon not clickable while other 3 icons work fine

### Initial Assessment ❌ WRONG
I incorrectly claimed the modal handling code was missing. **The code IS there** at lines 764-775.

### Actual Root Cause ✅ (from Kimi Code CLI)
The special handling EXISTS but has **mobile touch handling bugs**:

**Bug #1: Missing `e.preventDefault()` in onTouchEnd**
```jsx
onTouchEnd={() => setShowArcade(true)}  // ← No preventDefault!
// Causes ghost clicks, text selection, event bubbling
```

**Bug #2: Missing CSS touch protections**
Compare owner-mode tiles (have these):
- `userSelect: 'none'`
- `WebkitUserSelect: 'none'`
- `WebkitTouchCallout: 'none'`
- `touchAction: 'manipulation'`

Vs arcade div (line 770) only has:
```jsx
style={{ ...tileStyle, backgroundColor: getHeroBg(actionId), cursor: 'pointer' }}
```

**Bug #3: Possible HikariBoy crash on open**
If component throws on mount, React unmounts it immediately → "nothing happens"

### The REAL Fix (verified by Kimi Code CLI)
```jsx
if (actionId === 'game' || actionId === 'arcade') {
    return (
        <div
            key={actionId}
            onClick={() => setShowArcade(true)}
            onTouchStart={(e) => e.preventDefault()}
            onTouchEnd={(e) => {
                e.preventDefault();  // ← CRITICAL: Stop ghost clicks
                setShowArcade(true);
            }}
            style={{ 
                ...tileStyle, 
                backgroundColor: getHeroBg(actionId),
                cursor: 'pointer',
                userSelect: 'none',
                WebkitUserSelect: 'none',
                WebkitTouchCallout: 'none',
                touchAction: 'manipulation'
            }}
        >
            {tileContent}
        </div>
    )
}
```

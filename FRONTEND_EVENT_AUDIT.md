## 🚨 THE SMOKING GUN: Why Every Revenue Shows $NaN

### Bug #1: `total_revenue` vs `total_revenue_cents` (CATASTROPHIC)
The database stores `total_revenue_cents` (integer, cents). The frontend reads `event.total_revenue` (expected dollars). Nothing ever writes `total_revenue`.

**Broken locations in `OwnerEventsView.jsx`:**
| Line | Code | Result |
|------|------|--------|
| 170 | `events.reduce((a, e) => a + (e.total_revenue \|\| 0), 0)` | Total revenue modal = $0.00 |
| 291 | `(events.reduce(...) / 100).toFixed(0)` | Top stats card = $0 |
| 356 | `(event.total_revenue / 100).toFixed(0)` | **Every event card = $NaN** |
| 404 | `(event.total_revenue / 100).toFixed(0)` | **Event detail revenue = $NaN** |
| 407 | `((event.total_revenue / totalSold) / 100).toFixed(0)` | **Avg ticket = $NaN** |

`(undefined / 100).toFixed(0)` = `"NaN"`. Every stat card, every list card, every modal shows $NaN. This is the exact same bug found in the backend audit — it's live on the frontend too.

### Bug #2: `tier.price` vs `tier.price_cents` (CATASTROPHIC)
DB stores `price_cents` in `ticket_tiers` JSONB. Templates store `price` in dollars. The detail view reads `tier.price` expecting cents.

**`OwnerEventsView.jsx` line 437:**
```js
${(tier.price / 100).toFixed(0)}
```
- **For DB events:** `tier.price` is `undefined` → `$NaN` for every tier price
- **For templates:** `tier.price` is dollars (e.g., 1200) → `$12` instead of `$1200`

The tier prices in owner detail are completely broken for DB events and 100x wrong for templates.

## 🚨 WHY QR CODES WON'T SCAN AT THE DOOR

### Bug #3: QR Format Mismatch Between Ticket & Scanner
**`EventTicket.jsx` (line 196)** generates QR with:
```js
<QRCodeSVG value={booking.id} />
```
Where `booking.id` = `data.ticket_code` = `"TKT-ABC-123"`

**`TicketScanner.jsx` (line 107)** expects:
```js
if (raw.startsWith('FS-TICKET|')) { ... }
```

The standalone scanner (`TicketScanner.jsx`) will **never** scan a ticket generated by `EventTicket.jsx`. The owner check-in view (`CheckinView` in `OwnerEventsView.jsx`) looks up by `ticket_code` directly, which works — but only if the owner uses the built-in check-in, not the separate `TicketScanner` component.

**Two QR scanners exist with incompatible formats.**

## 🚨 WHY CUSTOMERS HIT A 404 AFTER PAYING

### Bug #4: Missing Route for Payment Return URL
**`App.jsx` line 532:**
```jsx
<Route path="/:tenantSlug/events" element={<EventThemeWrapper />} />
```

**`create-event-preference` edge function** redirects to:
```
/:tenantSlug/events/ticket?order_id=...&guest_token=...
```

React Router v6 exact matching means `/:tenantSlug/events` **does NOT match** `/:tenantSlug/events/ticket`. After a customer pays on Mercado Pago and is redirected back, they hit a **404 page**.

The `EventsView.jsx` useEffect (line 234) tries to read `order_id` from search params, but the component never mounts because the route doesn't match.

### Bug #5: Free Event Edge Function Uses Undefined Variable
**`create-event-preference` line 195:**
```js
redirect_url: `${APP_BASE_URL}/${branding.slug || 'demo'}/events/ticket?...`
```

`branding` is fetched on **line 202**, but this code runs on **line 195** (inside the free-event block). `branding` is `undefined`. Free event redirects produce `https://foodspotapp.vercel.app/undefined/events/ticket?...` — also a 404/broken URL.

## 🔴 CRITICAL BUGS FOUND

### 6. Base64 Images Bloat the Database (CRITICAL)
**`OwnerEventsView.jsx` lines 755-786:**
```js
const reader = new FileReader()
reader.onload = (evt) => patch('image_url', evt.target?.result || '')
reader.readAsDataURL(file)
```

Cover images stored as base64 data URLs directly in `events.image_url`. No Supabase Storage. No CDN. A 2MB photo = ~2.7MB base64 string in PostgreSQL. Every event list fetch downloads ALL base64 images. Row bloat. No optimization.

### 7. `parseFloat(t.price)` Returns NaN for Empty Price (CRITICAL)
**`OwnerEventsView.jsx` line 519:**
```js
price_cents: Math.round(parseFloat(t.price) * 100)
```

If a tier price input is empty string, `parseFloat("")` = `NaN`, and `Math.round(NaN)` = `NaN`. Database insert fails with opaque error. Customer sees "Publishing…" spinner forever or gets an alert with no useful message.

### 8. Promo Codes Are Pure Local State (CRITICAL)
**`PromosView` in `OwnerEventsView.jsx` (lines 1313-1449):**
- Hardcoded mock promos: `EARLYBIRD20`, `VIP15`
- `handleCreatePromo()` only mutates React state: `setPromos([...promos, newPromo])`
- **Never reads from `event_promo_codes` table**
- **Never writes to `event_promo_codes` table**
- The edge function (`create-event-preference`) DOES validate against the DB table, but the UI has no connection to it

Owners create promo codes that vanish on refresh. The edge function validates against empty DB rows.

### 9. Dead Hook: `useOwnerEvents.js` (HIGH)
File exists at `src/hooks/useOwnerEvents.js` with a realtime subscription. **Never imported anywhere.** `OwnerEventsView.jsx` does its own inline `fetchEvents()` (lines 94-123) without realtime. Owners must refresh to see new ticket sales or updated stats.

### 10. `useEvents.js` Only Shows Future Events (HIGH)
**Line 41:**
```js
.gte('start_date', new Date().toISOString())
```

Customer feed filters out any event whose `start_date` has already passed. An event for "today at 2 PM" disappears at 2:01 PM. No "Happening Now" tab. No past events archive.

### 11. `useEvents.js` Has No Realtime (HIGH)
Fetches on mount but has no Supabase realtime subscription. If an owner publishes a new event, customers must refresh the page to see it.

### 12. `useEvents.js` Silently Fails on Branding Mismatch (HIGH)
**Lines 24-34:**
```js
const { data: branding, error: brandingError } = await supabase
  .from('branding').select('business_id').eq('slug', tenantSlug).single()

if (brandingError || !branding?.business_id) {
  setEvents([]); setLoading(false); return;
}
```

If `branding.slug` doesn't match URL slug, the query returns empty array with no error message. Customer sees a blank page with "0 Events Near You" and no explanation. No toast, no "Events coming soon" message.

### 13. Check-in Counter Is Session-Only (MEDIUM)
**`CheckinView` in `OwnerEventsView.jsx` line 1246:**

The "checked in today" counter starts at 0 and increments locally. It does NOT query `event_checkins` for the actual count. Refresh resets it to 0. The `event.checkins` column is read for the stat card but `recalc_event_stats()` trigger may or may not update it.

They handle QR codes differently, use different libraries, and different backend endpoints. Maintenance nightmare.

## 🎯 SUMMARY: WHY YOUR EVENTS ARE "SAVED BUT NOT SHOWING" / "BROKEN"

### Revenue Shows $NaN
**Root cause:** Frontend reads `event.total_revenue` and `tier.price`, but DB stores `total_revenue_cents` and `price_cents`.
- 6 reads of `total_revenue` → all return `undefined` → `$NaN`
- 1 read of `tier.price` → returns `undefined` → `$NaN`

### Customer Gets 404 After Paying
**Root cause:** React Router route is `/:tenantSlug/events` (exact). MP redirect goes to `/:tenantSlug/events/ticket?...`. No match = 404.

### Free Event Redirect Broken
**Root cause:** `create-event-preference` edge function uses `branding.slug` before fetching `branding`.

### QR Code Won't Scan at Door (if using TicketScanner)
**Root cause:** `EventTicket` generates QR with `"TKT-XXX-NNN"`. `TicketScanner` expects `"FS-TICKET|orderId|..."`. Format mismatch.

### Events Disappear After Start Time
**Root cause:** `useEvents.js` filters `.gte('start_date', new Date().toISOString())`. Events vanish the moment they start.

### Customer Sees Fake Events Mixed with Real Ones
**Root cause:** `EventsView.jsx` always merges `[...mockEvents, ...dbEvents]`. 10 demo events (Pokemon, Anime Expo, etc.) appear for every restaurant.
